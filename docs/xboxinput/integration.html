1. Overview & Goal

The goal is to add Xbox controller support to zigsteroids by extracting the proven dual-path gamepad input logic from zig_xboxinput into a reusable module. The approach introduces a single new file — src/input.zig — that abstracts both keyboard and gamepad behind a unified API. The game's update() function then reads from this abstraction instead of calling raylib keyboard functions directly.

Why this approach is cleanest
  • Minimal change to game logic. Every rl.isKeyDown(.left) becomes input.isDown(.rotate_left). Game logic stays identical.
  • Keyboard still works. The abstraction checks both sources, so keyboard players see zero behavior change.
  • Dual-path logic is isolated. All joydev raw-reading, button mapping, axis normalization, and auto-detection lives in input.zig.
  • No dependency changes. Both projects already use the same raylib-zig commit.
  • Platform-safe. Raw joydev code is Linux-only; on Windows/macOS it compiles to a no-op.

3. Architecture: Input Abstraction Layer

The architecture introduces a single new module (src/input.zig) that sits between raylib's raw input API and the game's update() function. It abstracts away whether input comes from keyboard or gamepad, and — on Linux — whether the gamepad is read via raylib's mapped path or the raw joydev fallback.

3.1 The input.zig module structure

// src/input.zig
const std = @import("std");
const rl = @import("raylib");

// ── Game actions (what the game cares about) ──────────────────
pub const Action = enum {
    rotate_left,
    rotate_right,
    thrust,
    shield,
    shoot,
    pause,
    new_game,
};

// ── Internal input state ──────────────────────────────────────
pub const Input = struct {
    // Raw joydev state (Linux only)
    raw_js: if (is_linux) RawJoystick else void,
    raw_js_open: bool = false,
    use_raw: bool = false,
    detection_done: bool = false,
    connected: bool = false,

    // Edge-detection state buffers
    cur_gamepad_actions: [@typeInfo(Action).@"enum".fields.len]bool = @splat(false),
    prev_gamepad_actions: [@typeInfo(Action).@"enum".fields.len]bool = @splat(false),

    // ── Public API ──
    pub fn init() Input { ... }
    pub fn deinit(self: *Input) void { ... }
    pub fn update(self: *Input) void { ... }  // call once per frame
    pub fn isDown(self: *const Input, action: Action) bool { ... }      // held (continuous)
    pub fn isPressed(self: *Input, action: Action) bool { ... }          // edge-triggered
    pub fn rotationAmount(self: *const Input) f32 { ... }                // analog rotation
    pub fn isGamepadConnected(self: *const Input) bool { ... }
};

3.3 Platform conditional compilation

On non-Linux platforms, the raw joydev fields and methods compile to no-ops, and only the raylib mapped gamepad path is used. This keeps the build clean on Windows (where XInput works natively via raylib) and macOS.

pub const Input = struct {
    raw_js: if (is_linux) RawJoystick else void,
    // ...
};

pub fn init() Input {
    return .{
        .raw_js = if (is_linux) RawJoystick.init() else {},
        // ...
    };
}

4. Control Mapping

The game has 7 actions. Each maps to both a keyboard key and a gamepad input:

Game ActionKeyboardGamepad ButtonGamepad AxisType
rotate_left ← Left arrow D-pad left (left_face_left) Left stick X < 0 analog
rotate_right → Right arrow D-pad right (left_face_right) Left stick X > 0 analog
thrust ↑ / W A button (right_face_down) RT (right trigger) > 0.1 analog
shield ↓ Down arrow B button (right_face_right) LT (left trigger) > 0.1 digital
shoot Space / LMB A button (right_face_down) — edge-triggered
pause H / P Start (middle_right) — edge-triggered
new_game 1 Start (middle_right) — edge-triggered
Design decisions explained

Why A for both thrust and shoot?

Thrust uses RT (right trigger) for analog intensity with a threshold so light touches don't fire. But A button (right_face_down) is also accepted as a digital alternative for simplicity. Shoot uses A button — the natural "fire" button on any gamepad. When A is pressed, shoot takes priority over thrust (checked first in the action resolution).

Why analog rotation?

The left stick X axis drives rotation speed proportional to stick deflection, with a dead zone. This is the biggest gameplay improvement: the ship turns faster when the stick is pushed further. D-pad left/right provides digital fallback. See §5 for implementation details.

Why shield on B and LT?

B button (right_face_right) is the simplest digital input. LT (left trigger) is an analog alternative that could enable partial shields in the future. Either input activates the shield.

Why Start for both pause and new_game?

Start (middle_right) pauses during gameplay and starts a new game on the game-over screen. The context disambiguates: new_game is only checked when state.gameOver == true, and pause is only checked otherwise. No conflict.

5. Analog Rotation Support

Currently, rotation is digital: ROT_SPEED = 2 revolutions per second, applied as a constant when the key is held. With analog stick input, rotation speed can scale with stick deflection — the ship turns faster when the stick is pushed further.

Implementation in input.zig

const DEADZONE: f32 = 0.15;

pub fn rotationAmount(self: *const Input) f32 {
    // Returns -1.0..1.0 for rotation input
    // Keyboard: -1, 0, or 1 (digital)
    // Gamepad left stick X: analog with dead zone

    var val: f32 = 0;

    // Keyboard
    if (rl.isKeyDown(.left))  val -= 1.0;
    if (rl.isKeyDown(.right)) val += 1.0;

    // Gamepad (analog overrides keyboard when stick is pushed)
    if (self.connected) {
        const lx = if (self.use_raw) self.raw_js.axes[0]
                   else rl.getGamepadAxisMovement(0, .left_x);
        if (@abs(lx) > DEADZONE) {
            val = lx;  // analog takes over
        }
        // D-pad as digital fallback
        if (self.gamepadButtonDown(.left_face_left))  val -= 1.0;
        if (self.gamepadButtonDown(.left_face_right)) val += 1.0;
    }

    return @max(-1.0, @min(1.0, val));
}

6. Edge-Triggered Button Detection

raylib provides isGamepadButtonDown (held state) but no isGamepadButtonPressed (edge-triggered). The raw joydev path also only provides held state. For actions like shoot, shield, pause, and new_game, we need edge detection — trigger once on press, not every frame while held.

Solution: Track previous-frame button state

pub const Input = struct {
    cur_gamepad_actions:  [N]bool = @splat(false),
    prev_gamepad_actions: [N]bool = @splat(false),

    pub fn update(self: *Input) void {
        // 1. Move current → previous
        self.prev_gamepad_actions = self.cur_gamepad_actions;

        // 2. Poll gamepad, run auto-detection
        self.pollGamepad();
        self.detectMode();

        // 3. Snapshot current gamepad action states
        for (0..N) |i| {
            const action: Action = @enumFromInt(i);
            self.cur_gamepad_actions[i] = self.checkGamepadAction(action);
        }
    }

    pub fn isPressed(self: *const Input, action: Action) bool {
        const idx = @intFromEnum(action);
        // Edge: gamepad pressed this frame but not last, OR keyboard key pressed
        return (self.cur_gamepad_actions[idx] and !self.prev_gamepad_actions[idx])
            or self.keyboardKeyPressed(action);
    }

    pub fn isDown(self: *const Input, action: Action) bool {
        const idx = @intFromEnum(action);
        // Held: gamepad down OR keyboard down
        return self.cur_gamepad_actions[idx] or self.keyboardKeyDown(action);
    }
};
Important
input.update() must be called exactly once per frame before any isPressed() or isDown() calls. This ensures the previous-state buffer is correctly snapshot and edge detection works.

9. What NOT to Do

Don'tWhy
Don't merge zig_xboxinput as a dependency It's not a library — it's a standalone app. Extracting the reusable parts into input.zig is cleaner.
Don't use zig_xboxinput's rendering code None of drawCircleButton, drawStick, drawTriggerBar, layout, or diagnostics code is needed.
Don't change the build system or dependencies Both projects already share the same raylib-zig commit. input.zig is a local import.
Don't remove keyboard support The abstraction checks both keyboard and gamepad. Keyboard players should see zero behavior change.
Don't add platform-specific build targets Use @import("builtin").os.tag for conditional compilation within input.zig itself.
Don't over-engineer the Action enum 7 actions is all the game needs. Resist adding remapping, multiple controllers, or config files at this stage.

11. Summary

The core idea

Extract the dual-path gamepad input logic from zig_xboxinput into a reusable src/input.zig module, then replace zigsteroids' direct raylib keyboard calls with calls to that module's unified API.

The changes break down as:

1 new file (input.zig) 1 file copied (udev rules) 1 file modified (main.zig — 10 call sites) Makefile + README updated

The game logic changes are mechanical find-and-replace (10 call sites), plus optional analog rotation. No new dependencies, no build system changes, no removed features, and keyboard players see zero difference.
